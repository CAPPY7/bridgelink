SECTION 3: ARCHITECTURE
=====================================================================
Discovery
  - Both devices advertise and browse a Bonjour/mDNS service, for
    example "_bridgelink._tcp", on the local network.
  - Include a device ID and display name in the TXT record.

Pairing (one time)
  - The Mac shows a QR code containing: Mac device ID, LAN
    address(es), port, public-key fingerprint, and a one-time pairing
    token (expires in 2 minutes).
  - The Android app scans it (or the user types a 6-digit PIN as a
    fallback).
  - Both sides exchange and store each other's public keys. After
    pairing, connections are authenticated by those keys.

Transport and security
  - TLS 1.3 with per-device self-signed certificates. Pin the peer
    certificate/public key after pairing. Reject any unpaired or
    mismatched peer.
  - On top of TLS, use end-to-end encryption for anything that goes
    through a relay (e.g., X25519 key agreement + ChaCha20-Poly1305 or
    AES-GCM). Use well-known libraries only (libsodium, CryptoKit,
    Tink, BouncyCastle). Never invent your own crypto.
  - Everything is off by default until the user grants each permission
    and enables each feature. Provide a per-feature toggle on both
    sides.

Connection management
  - Auto-reconnect with exponential backoff.
  - Heartbeat/ping every 15-30 s; detect dead links quickly.
  - Handle network changes (Wi-Fi switch, sleep/wake, IP change).
  - Message queue with retry so nothing is lost if the link drops
    briefly. Use message IDs for de-duplication.

Data
  - Local history DB on both sides (clipboard, notifications, SMS,
    transfers) with search and a retention setting (default 30 days)
    plus a "clear all data" button.

Repository layout (monorepo):
  /android          Android Studio project
  /macos            Xcode project
  /relay            optional relay server
  /docs             PROTOCOL.md, ARCHITECTURE.md, DECISIONS.md,
                    SERVICES.md, SETUP_FOR_OWNER.md, USER_GUIDE.md,
                    PERMISSIONS.md, TROUBLESHOOTING.md
  /.github/workflows  CI + release workflows
  README.md         overview, screenshots (placeholders ok), install
                    steps, build steps, feature checklist

SECTION 4: FEATURES TO BUILD (all 25 items)
=====================================================================

EASY
 1. Send files, links, and text between devices (both directions),
    with progress, resume on failure, and a transfer history. Large
    files are chunked and streamed (no loading the whole file in RAM).
 2. Android share sheet integration ("Share to Mac" appears in the
    Android share menu) AND a drag-and-drop target on the Mac menu bar
    icon / window.
 3. Notification mirroring. Android NotificationListenerService
    forwards notifications to the Mac (app name, title, text, icon).
    Show as native macOS notifications. Support reply/action buttons
    sent back to the phone, dismissing on one device clears the other.
    Per-app allow/block list.
 4. Remote media control: play/pause/next/previous/volume from the Mac
    for whatever is playing on the phone (MediaSession), and show the
    now-playing title/artist.
 5. Battery and charging status of the phone shown in the Mac menu bar
    (and the Mac's battery visible on the phone). Low-battery alerts.
 6. Find my phone: a button on the Mac that makes the phone ring at
    full volume even on silent (use the alarm stream), plus flash and
    a "stop ringing" notification/button on the phone.
 7. OTP auto-copy: detect verification codes in incoming
    notifications/SMS and copy them to the Mac clipboard automatically
    (toggleable), with a small confirmation toast.
 8. Open a link on the other device: send a URL from phone to the Mac
    default browser and vice versa (a mini Handoff for links).
 9. Phone as trackpad, keyboard, and presentation remote for the Mac:
    touch area for pointer, tap/drag/scroll, a text-input mode, and
    slide next/previous controls. Mac side uses CGEvent (needs
    Accessibility permission; guide the user through it).

POSSIBLE, WITH SOME PAIN (handle the platform limits described)
10. Clipboard sync. Mac -> phone is automatic. Phone -> Mac: since
    Android 10 apps cannot read the clipboard in the background, so
    provide ALL of these: a "Send clipboard" Quick Settings tile, a
    share-sheet action, a persistent-notification button, an optional
    floating bubble/overlay, and an OPTIONAL accessibility-service
    based method (clearly explained and opt-in). Tell the user which
    method is active.
11. SMS read and reply from the Mac. Android side uses the SMS
    permissions and the user must set it as needed; because Google
    Play restricts SMS permissions, the primary distribution is the
    APK from GitHub Releases (and optionally F-Droid). Support
    sending, receiving, conversation threads, and contact names
    (READ_CONTACTS, opt-in).
12. Screen mirroring: Android MediaProjection captures the screen,
    encodes H.264 (MediaCodec), streams to the Mac, which decodes and
    shows it in a window (VideoToolbox). User approves the capture
    prompt each session. Target 30 fps on LAN with adaptive bitrate.
13. Control the phone from the Mac while mirroring: mouse clicks,
    drags, scrolls, and keyboard input from the Mac window are sent to
    the phone. Primary method: an Android AccessibilityService
    (gestures). Secondary optional method: ADB over Wi-Fi if the user
    enables wireless debugging. Document both in USER_GUIDE.md.
14. Phone as Mac webcam and microphone. Android streams camera
    (CameraX) and mic audio to the Mac. On the Mac, expose them
    as a virtual camera (CoreMediaIO Camera Extension) and a virtual
    audio input if possible. This is the hardest macOS piece: build it
    as an isolated module; if signing/entitlements block it, ship the
    stream viewer window first (so video works in a preview window and
    can be screen-captured), document the limitation, and mark the
    virtual-device part as "experimental" in the README.
15. Shared folder: browse the phone's files from Finder. Run a WebDAV
    (or SFTP) server on the phone, bound to the paired connection only
    (authenticated, never open to the whole LAN). The Mac app has a
    "Mount phone storage" button that mounts it in Finder. Use Android
    Storage Access Framework / MANAGE_EXTERNAL_STORAGE as appropriate
    and let the user pick which folders are shared.
16. Auto-lock the Mac when the phone moves away. Use Bluetooth
    LE RSSI/proximity (or loss of connection with a grace period) to
    detect "phone left". Lock the Mac screen when it does. Make the
    threshold and delay configurable. DO NOT attempt auto-unlock
    (not supported); say so in the UI.
17. Sync while away from home. Implement a relay mode so devices stay
    connected on different networks:
      Option A (preferred default): support connecting over
        Tailscale/WireGuard IPs if the user has them (just allow
        manual host entry and a saved remote address).
      Option B: a tiny relay server (/relay) using WebSockets that
        forwards ONLY end-to-end-encrypted messages; deploy it to a
        free tier (Cloudflare Workers/Fly.io/Render) and document it.
      Use FCM (Firebase Cloud Messaging) data pushes ONLY as a
        wake-up signal so the Android app can reconnect; no sensitive
        content in pushes.
    Local network is always tried first; relay is the fallback.

PRODUCT IDEAS
18. Unified inbox: one searchable timeline of notifications, OTPs, and
    SMS with filters (app, type, date), full-text search, pin/star,
    and quick actions (copy code, reply).
19. Cross-device clipboard history: last N items (default 100) on both
    devices, searchable, pin items, tap to re-copy to either device,
    with a "sensitive item" filter (don't store things copied from
    password managers).
20. Scan to Mac: a document-scanner screen on Android (ML Kit Document
    Scanner or CameraX + edge detection), outputs a clean multi-page
    PDF, and sends it to a chosen Mac folder automatically (and
    optionally runs OCR).
21. Automations: simple rules like "when phone joins <home Wi-Fi>, sync
    new photos to ~/Pictures/PhoneSync" or "when phone charging
    starts, ..." Build a small rules UI with triggers (Wi-Fi, charging,
    time, Bluetooth device) and actions (sync folder, send file,
    notify, lock Mac).
22. Quick-drop menu bar: click the menu bar icon, drag a file onto it,
    pick the target device (or it auto-picks the only one), done. Also
    supports dropping text and links.

SECURITY
23. One-time pairing with QR code or 6-digit PIN (see Section 3).
    Provide "Forget device" and "Re-pair" on both sides.
24. End-to-end encryption for all data (see Section 3), including relay
    traffic.
25. Certificate / public-key pinning after pairing, with a clear
    warning screen if the peer's key ever changes.

SECTION 5: PLATFORM CONSTRAINTS YOU MUST RESPECT
=====================================================================
Android
  - Android kills background apps aggressively (Xiaomi, Oppo, Vivo,
    Samsung, OnePlus, Huawei). Implement:
      * Foreground Service with a persistent, low-priority
        notification and the correct foregroundServiceType
      * A first-run "Keep me connected" setup wizard that requests
        battery-optimization exemption and links to
        https://dontkillmyapp.com style per-brand instructions
        (write the in-app text yourself)
      * FCM wake-up for reconnection
      * Boot-completed receiver to restart the service
  - Request permissions only when needed, one feature at a time, with
    a clear explanation screen before each system prompt. List every
    permission and why in docs/PERMISSIONS.md.
  - Handle Android 13+ notification permission, Android 14 foreground
    service types, and scoped storage rules.
  - Background clipboard reads are blocked; use the methods in
    Feature 10.

macOS
  - First launch will trigger prompts: Local Network, Notifications,
    Accessibility (for input control), Screen Recording (if needed),
    Camera/Microphone (virtual devices), and Full Disk/Files access as
    required. Build a friendly onboarding window that shows the status
    of each permission with a "Fix it" button that opens the right
    System Settings pane.
  - Include the needed Info.plist keys (NSLocalNetworkUsageDescription,
    NSBonjourServices, etc.) and entitlements.
  - Run as a menu bar agent (LSUIElement) with a "Launch at login"
    option (SMAppService).

Things that are NOT possible and must NOT be attempted
  - iMessage / FaceTime on Android
  - AirDrop / Handoff / Universal Clipboard with Apple's own protocol
  - Unlocking the Mac with the phone
  - Silently changing system settings (hotspot, airplane mode)
  - Running Android apps natively in macOS windows
  - Phone call audio routed to the Mac
  Do not add placeholders or fake buttons for these.

SECTION 7: QUALITY REQUIREMENTS
=====================================================================
- The code must actually compile and run. Do not leave TODO stubs for
  core flows. If a feature must be partial, say so in the README.
- Write unit tests for protocol encoding/decoding, pairing, crypto
  helpers, chunked transfer, and reconnect logic. Add at least one
  integration test that runs a fake peer.

  injection where helpful, coroutines/async-await, no blocking the main
  thread.
- Handle errors visibly: show friendly messages, never crash silently,
  log with a toggle for debug logs, and add an "Export diagnostics"
  button (no personal content in it).
- Privacy: no analytics, no telemetry, no third-party trackers. All
  data stays on the two devices (or encrypted through the relay).
- Performance: idle battery usage must be low; avoid wake locks except
  during active transfers/streams.
- Accessibility: labels for screen readers, sensible touch targets,
  dark mode.
- Keep dependencies minimal and well-maintained; pin versions.

SECTION 8: CI/CD AND RELEASE (GitHub)
=====================================================================
Create these GitHub Actions workflows:

1. ci.yml (on push and pull request)
   - Android: set up JDK, Gradle cache, run lint + unit tests,
     assembleDebug.
   - macOS: run on a macOS runner, xcodebuild build + test.
   - Relay: lint + tests.

2. release.yml (on tag push "v*")
   - Android: build a release APK, sign it using the keystore from
     GitHub Secrets (ANDROID_KEYSTORE_BASE64, ANDROID_KEY_ALIAS,
     ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_PASSWORD). If secrets are
     missing, fall back to a debug-signed APK and say so in the
     release notes.
   - macOS: build the .app in Release mode, package as .dmg (or .zip),
     and attach to the Release. Sign/notarize only if Apple secrets
     exist; otherwise ship ad-hoc signed and include install
     instructions (see Section 9).
   - Auto-generate release notes (changelog from commits).
   - Upload all artifacts to the GitHub Release.

3. Optionally pages.yml to publish docs/ and a simple landing page
   with download buttons to GitHub Pages.

Also generate a one-time script (scripts/generate-android-keystore.sh)
that creates the Android signing key and prints the exact commands to
add it to GitHub Secrets.
